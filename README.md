# House_Prices
## Kaggle-ის კონკურსის მოკლე მიმოხილვა
ეს პროექტი მუშაობს Kaggle-ის კონკურსზე https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques. მონაცემები შეიცავს 1460 სახლის ინფორმაციას, სადაც 79 feature აღწერს სახლის სხვადასხვა მახასიათებელს. target ცვლადი არის SalePrice, რომელიც უნდა ვიწინასწარმეტყველოთ.
პროექტის მიზანია სხვადასხვა ექსპერიმენტების ჩატარება მონაცემთა გასუფთავების (Data Cleaning), ფუნქციათა შერჩევისა (Feature Selection) და მოდელირების ეტაპებზე, რათა დავინახოთ, რომელი მიდგომა იძლევა საუკეთესო შედეგს.

## მიდგომა პრობლემის გადასაჭრელად
თავდაპირველად დავაკვირდი მონაცემებს და მათში არსებულ გამოტოვებულ მნიშვნელობებს(NaN). ჩავატარე რამდენიმე ექსპერიმენტი:
  1.Baseline: ყველა სვეტის შენარჩუნება.
  2.Missing Value Thresholding: იმ სვეტების ამოშლა, სადაც მონაცემთა 40%-ზე მეტი აკლდა.
  3.Feature Selection: RFE (Recursive Feature Elimination) ალგორითმის გამოყენება.
  4.Modeling: გამოვიყენეთ Lasso რეგრესია (სხვადასხვა ალფა პარამეტრით) და Decision Tree.
ყოველი ეტაპი დავლოგე MLflow-ის მეშვეობით DagsHub-ზე, რათა შემედარებინა მეტრიკები (RMSE).

## რეპოზიტორიის სტრუქტურა
  * model_experiment.ipynb: ძირითადი notebook, სადაც ხდება მონაცემთა დამუშავება, ექსპერიმენტები (Baseline, Dropping, RFE) და მოდელების ტრენინგი.
  * model_inference.ipynb: სატესტო მონაცემებზე პროგნოზის გაკეთება Model Registry-დან საუკეთესო მოდელის ჩატვირთვით.
  * README.md: მოცემული ფაილი პროექტის აღწერით.

## EDA
მონაცემების გაანალიზებისას აღმოჩნდა, რომ ზოგიერთ ცვლადში (მაგ: PoolQC, MiscFeature, Alley) მონაცემების 90%-ზე მეტი გამოტოვებული იყო. ამის გამო გადავწყვიტე, რომ შემედარებინა "ყველა სვეტის დატოვება" და "ცარიელი სვეტების ამოშლა".

## Data Separation
მონაცემები train_test_split-ით შემთხვევითად გავყავი 80/20 შეფარდებით.

## Cleaning მიდგომები და Feature Engineering
  * Nan მნიშვნელობების დამუშავება: კატეგორიული ცვლადებისთვის გამოვიყენე "None", რაც ნიშნავს, რომ სახლს არ აქვს კონკრეტული მახასიათებელი (მაგ:       აუზი). რიცხვითი ცვლადებისთვის გამოვიყენე მედიანა.
  * One-Hot Encoding: ყველა კატეგორიული ცვლადი გადავიყვანე რიცხვით ფორმატში pd.get_dummies-ით.
  * Alignment:  align ფუნქციით უზრუნველვყავი, რომ Train და Validation სეტებს ჰქონოდათ იდენტური სვეტები.

## Feature Selection
პროექტში გამოვიყენე ორი ძირითადი გზა:
  * Manual Thresholding: ამოვშალე სვეტები, სადაც NaN > 40%. ამან ფუნქციათა რაოდენობა 301-დან 274-მდე შეამცირა.
  * RFE (Recursive Feature Elimination): გამოვიყენე LinearRegression როგორც estimator, რათა შემერჩია საუკეთესო 50 ფუნქცია.

## Training
### ტესტირებული მოდელები:
  1. Baseline: "Keep All" სტრატეგია
     პირველ ექსპერიმენტში (Keep_All_Columns) მიზანი იყო მინიმალური ჩარევით მიმეღო შედეგი.
     Preprocessing: ყველა კატეგორიული ცვლადი შეივსო "None"-ით, ხოლო რიცხვითი — მედიანით.
     Encoding: One-Hot Encoding-ის შემდეგ მივიღე 301 ფუნქცია.
     შედეგი: RMSE — 33,247.10.
  2. Feature Pruning: 40% Threshold (საუკეთესო მოდელი)
     მეორე ექსპერიმენტში (Dropping_40%) გამოვიყენე უფრო აგრესიული გასუფთავების მეთოდი.
     ავტომატურად გამოვთვალე თითოეული სვეტისთვის NaN მნიშვნელობების წილი. ის სვეტები, სადაც სიცარიელე 40%-ს აღემატებოდა, სრულად ამოვშალე
     (მაგ: PoolQC, MiscFeature).
     Alignment: გამოვიყენე X_train_enc.align(X_val_enc, join='left'). ეს უზრუნველყოფს, რომ ვალიდაციის სეტს ჰქონდეს ზუსტად იგივე სვეტები, რაც
     ტრეინინგს, მაშინაც კი, თუ ზოგიერთი კატეგორია ვალიდაციაში არ გვხვდება.
     შედეგი: RMSE შემცირდა 32,400.80-მდე. ეს გახდაცსაუკეთესო მოდელი.
  3. Feature Selection: RFE (Recursive Feature Elimination)
     აქ ვცადე ფუნქციების რაოდენობის ხელოვნურად შეზღუდვა.
     LinearRegression-ზე დაფუძნებული RFE-ით შევარჩიე 50 საუკეთესო ფუნქცია.
     Lasso-მ ამ 50-დან მხოლოდ 29 ფუნქციას მიანიჭა წონა, დანარჩენი გაანულა.
     შედეგი: RMSE გაიზარდა 35,079.03-მდე. გამოვიდა, რომ ზედმეტმა შეზღუდვამ მოდელს მნიშვნელოვანი ინფორმაცია დაუკარგა.
  4. Hyperparameter Optimization:
     RFE-ს ბაზაზე ჩავატარე დამატებითი ექსპერიმენტი რეგულარიზაციის ძალის შესამოწმებლად:
     Lasso (Alpha=100): მოდელმა 50 ფუნქციიდან მხოლოდ 29 დატოვა. მაღალმა რეგულარიზაციამ მოახდინა ხმაურის ფილტრაცია და მოდელი აიძულა, ფოკუსირებულიყო მხოლოდ      ყველაზე გავლენიან ცვლადებზე (მაგ: საერთო ფართობი, ხარისხი). ამან შეამცირა ხმაური (noise) და გააუმჯობესა ვალიდაციის ქულა.
     Lasso (Alpha=10): მოდელმა შეინარჩუნა 50-ივე ფუნქცია, რამაც RMSE -795.92-ით გააუარესა (35,874.94). დაბალი alpha-ს პირობებში მოდელმა დაიწყო ზედმეტი         დეტალების "სწავლა", რაც ხელს უშლიდა მას ახალი მონაცემების სწორად პროგნოზირებაში.
     დაბალი alpha იწვევს მოდელის overfitting-ს, რადგან ის ცდილობს, ყველა, მათ შორის ნაკლებმნიშვნელოვან ფუნქციასაც, მიანიჭოს წონა. სახლის
     ფასების პროგნოზირებისას ძლიერი რეგულარიზაცია (alpha=100) უფრო სტაბილურ შედეგს იძლევა.
  6. Decision Tree Regressor:
     გადავწყვიტე, გამომეყენებინა არაწრფივი მოდელიც. გამოვიყენე max_depth=5, რათა თავიდან ამეცილებინა სრული ოვერფიტინგი.
     შედეგი: Decision Tree-მ აჩვენა ყველაზე მაღალი ცდომილება (RMSE: 43,956.42).
     სახლის ფასების მონაცემებში ფუნქციებსა და ფასს შორის კავშირი მეტწილად წრფივია (მაგ: ფართობის ზრდა პირდაპირპროპორციულად ზრდის ფასს). Decision
     Tree-მ, მიუხედავად სიღრმის შეზღუდვისა, ვერ აჩვენა ისეთივე სიზუსტე, როგორიც რეგულარიზებულმა Lasso-მ. ამ ამოცანისათვის წრფივი მოდელები უფრო ეფექტური
     აღმოჩნდა.

### შედეგების შედარება:
  * საუკეთესო შედეგი აჩვენა Lasso (Dropped 40%) მოდელმა.
  * RFE-ს გამოყენებამ RMSE ოდნავ გაზარდა, რაც ნიშნავს, რომ 50 ფუნქციამდე დაყვანით გარკვეული მნიშვნელოვანი ინფორმაცია დაიკარგა.
  * ჰიპერპარამეტრი alpha=100 უფრო ეფექტური აღმოჩნდა, ვიდრე alpha=10, რადგან უფრო მაღალი რეგულარიზაცია უკეთ ებრძვის ოვერფიტინგს.
